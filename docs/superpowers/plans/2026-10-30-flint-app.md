# Flint (app PWA) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Construir o Flint, um PWA de academia para iPhone com dados locais, três mascotes animados, dados de exemplo e deploy no GitHub Pages. As notificações push ficam no plano 2 (`2026-10-30-flint-push.md`).

**Architecture:** É uma SPA em React. Todos os dados ficam no IndexedDB, via Dexie. Tudo o que é "conquista" vem de funções puras em `src/domain/` aplicadas ao histórico. Isso inclui XP, PRs, medalhas, sequência, humor, meta de água e sugestão de carga. Essas funções nunca são persistidas e são testadas com Vitest. A UI lê o banco com `useLiveQuery` e chama o domínio. Os mascotes e a água são portados do mockup aprovado como módulos imperativos, e um componente React fino embrulha cada um.

**Tech Stack:**
- Vite 6, React 19, TypeScript (strict)
- react-router (HashRouter)
- Dexie 4 + dexie-react-hooks
- vite-plugin-pwa
- @fontsource-variable/archivo
- Vitest + @testing-library/react + fake-indexeddb + jsdom
- GitHub Actions → GitHub Pages

**Spec:** `docs/superpowers/specs/2026-10-30-flint-design.md`. A referência visual viva está em `docs/reference/mockup-v16.html` e `docs/reference/mascots.js`.

## Global Constraints

- O nome "Flint" aparece em um só lugar: `src/brand.ts` exporta `APP_NAME`. O manifest e o `index.html` leem de lá via config do Vite.
- UI em pt-BR. Unidades em kg e ml. Datas e "dia" usam sempre o fuso local, no formato `YYYY-MM-DD` gerado por `localDay(date)`. Nunca usar `toISOString().slice(0,10)`.
- Paleta (tokens CSS em `src/styles/tokens.css`):
  - `--bg #0E0A12`, `--surface #17111D`, `--surface-2 #211929`, `--line rgba(255,235,245,.07)`
  - `--text #F5F0F7`, `--muted #A193AA`, `--faint #6E6177`
  - `--crimson #E5163E`, `--crimson-hi #FF4D6D`, `--crimson-lo #8E0B26`
  - `--gold #F5B700`, `--gold-hi #FFE38A`
  - `--water #3B82F6`, `--water-hi #8CB8FF`
- Cor por métrica: treino = carmesim, água = azul, PR/conquista = ouro.
- Fonte Archivo variável (wdth 62–125, wght 400–900), auto-hospedada.
- Logo: `brand/flint-logo.svg` (ícone, carmesim sobre `#1C1B20`) e `brand/flint-mark.svg` (marca). Usar como estão.
- Nada de coração, batimento ou eletro em ícone, texto ou animação.
- A água usa o canvas de molas do mockup. Nunca usar onda CSS em loop.
- Os mascotes vêm do port de `docs/reference/mascots.js` (estilo "nub", sem tronco). Não redesenhar.
- Toda animação respeita `prefers-reduced-motion`. A resposta ao toque vem no `pointerdown`, com `:active { transform: scale(.97) }`.
- No desktop, o app fica centralizado com `max-width: 430px`.
- Abertura: tela de carregamento de no máximo 1,5 s e depois a aba Hoje. Sem onboarding.
- Todas as regras e números do §8 do spec ficam em `src/domain/rules.ts`.
- Repositório público `flint`. Vite `base: './'` com HashRouter, para funcionar em qualquer subcaminho do Pages.

## Review Focus

1. **App fechado no meio do treino:** ao reabrir, o treino em andamento volta com as séries marcadas (Task 8).
2. **Vírgula decimal do teclado do iPhone:** "22,5" em kg vira 22.5, e entradas vazias ou inválidas não salvam `NaN` (Task 8).
3. **Virada do dia:** água registrada às 23:59 conta no dia certo, e o reset diário segue a meia-noite local, não UTC (Tasks 2 e 6).
4. **Exercício usado no histórico:** excluir um exercício próprio ou removê-lo da rotina não quebra o histórico nem os gráficos. Ele é arquivado, nunca apagado (Tasks 3 e 7).
5. **Backup inválido ou de outra versão:** a importação falha com mensagem e não apaga os dados atuais (Task 12).

### Task 4: Domínio — força, rotina e progresso

**Files:**
- Create: `src/domain/strength.ts`, `src/domain/routine.ts`, `src/domain/progress.ts`
- Test: `tests/domain/strength.test.ts`, `tests/domain/routine.test.ts`, `tests/domain/progress.test.ts`

**Interfaces:**
- `epley(kg: number, reps: number): number` calcula `kg * (1 + reps/30)`. Com `reps === 1`, devolve `kg`.
- `findPRs(sessions: Session[]): PR[]`, com `PR { sessionId; exerciseId; kind: 'e1rm' | 'repMax'; kg; reps; at: number }`.
  - Percorre as sessões finalizadas em ordem cronológica e conta só séries `done`.
  - Gera `repMax` quando a carga é maior do que qualquer anterior para o mesmo nº de reps.
  - Gera `e1rm` quando o 1RM estimado é maior que o máximo anterior.
  - A primeira vez que um exercício aparece não gera PR.
- `suggestOverload(item: TemplateItem, last: Entry | undefined, eq: Equipment): { kg: number; text: string } | null`
  - Se todas as séries `done` atingiram `repMax`: `kg = maior carga + RULES.overloadKg[eq]`, com texto `Bateu ${repMax} reps em todas — tenta ${inc} kg a mais`.
  - Senão: mesma carga, com texto `Repete ${kg} kg e busca +1 rep`.
  - Sem histórico: `null`.
- `nextTemplate(templates: Template[], sessions: Session[]): Template | null`: o template seguinte (por `order`, circular, ignorando arquivados) ao `templateId` da última sessão finalizada que tinha template. Sem histórico, devolve o primeiro.
- `lastEntryFor(exerciseId, sessions): Entry | undefined`
- `plates(targetKg: number, barKg = 20, avail = [25, 20, 15, 10, 5, 2.5, 1.25]): { perSide: number[]; remainder: number }`
- `sessionStats(s: Session, lib: Exercise[]): { durationMin; volumeKg; muscles: Muscle[] }`
- `exerciseSeries(exerciseId, sessions): { day; maxKg; e1rm; volume }[]`
- `muscleVolume(sessions, fromDay, toDay, lib): Record<Muscle, number>`: o músculo primário conta 1× e cada secundário 0,5×.
- `dayIntensity(sessions, days): Record<string, number>`: volume normalizado de 0 a 1, para o calendário.

- `waterGoalMl(settings, latestKg?: number): number`. Se houver override, usa `settings.waterGoalMl`. Senão, `round(35·kg / 250)·250`. Sem peso, 2500.
- `dailyMedals(day, data): MedalId[]`, com ids `'treino' | 'hidratado' | 'recorde' | 'dia-completo'`, no máximo um de cada por dia.

- `computeXP(data, today): { xp: number; stage: StageId; next: number | null }`. O XP soma todos os treinos, PRs, dias com água na meta e medalhas, usando `RULES.xp`.
- `missedTrainDays(sessions, trainDays, today): number`: quantos dias marcados seguidos, antes de hoje e desde o último treino, ficaram sem treino.
- `mood(sessions, trainDays, today): 'happy' | 'sad'`. Fica `'sad'` quando `missedTrainDays(...) >= RULES.sadAfterMissedTrainDays`.
- `GameData = { sessions; water; weights; settings; library }`

  - Rotina A–F realista.
  - 6 semanas, seg–sáb, com cargas subindo e algumas falhas de reps.
  - Água diária entre 60% e 120% da meta.
  - Peso caindo levemente de 82 para 79,5 kg.
  - `settings.demo = true` e `trainDays = [1,2,3,4,5,6]`.
