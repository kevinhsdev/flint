# Flint fase 2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Levar o Flint ao nível "app pelo qual se paga": pesquisa inicial com plano gerado, tela de água, nova barra de navegação, corpo anatômico refeito e seis recursos premium.

**Architecture:** Mesmo app da fase 1: React 19 + TS estrito, HashRouter, Dexie. A lógica nova é de funções puras em `src/domain/` (plano, aquecimento, platô, previsão, retrospectiva), testadas primeiro. As telas novas ficam em `src/screens/`. Imagens compartilháveis saem de `<canvas>` local; os sons, de Web Audio sintetizado.

**Tech Stack:** Vite 8, React 19, TypeScript, Dexie 4 + dexie-react-hooks, vite-plugin-pwa, Vitest + Testing Library (jsdom, fake-indexeddb).

**Spec:** `docs/superpowers/specs/2026-10-30-flint-fase2-design.md`. A fase 1 está em `docs/superpowers/specs/2026-10-30-flint-design.md`.

## Global Constraints

- Português do Brasil em toda a interface. Datas sempre por `localDay()`, nunca UTC.
- Sem dependências novas. Animação em CSS ou na engine de molas existente; imagem por canvas; som por Web Audio.
- Tudo funciona offline. iPhone PWA: nada de `navigator.vibrate`, widgets ou Live Activities.
- `prefers-reduced-motion` desliga movimento decorativo (barra, ícones, telas de plano e retrospectiva).
- Animações nunca atrasam ações repetidas, como registrar série ou beber água.
- Meta de água continua `RULES.waterMlPerKg = 35`, arredondada a `RULES.waterRoundMl = 250`.
- Séries de aquecimento não contam para volume, recordes, XP nem músculos.
- Backup sobe para versão 2 e continua aceitando backups versão 1.
- Inputs com fonte ≥ 16px (sem zoom no iOS). Hovers só dentro de `@media (hover: hover) and (pointer: fine)`.
- TDD em todo código de produção; `npx tsc --noEmit -p .` limpo; suíte inteira verde ao fim de cada tarefa.

## Review Focus

1. **Pesquisa com valores extremos:** peso 300 kg, altura 120 cm, idade 15 ou 90, 2 dias em casa e 30 min. Espera-se um plano válido (nunca treino vazio, nunca exercício de equipamento indisponível) e meta de água limitada. Teste em Task 3 e Task 6.
2. **Aquecimento com carga pequena** (barra ≤ 20 kg, halteres 4 kg, máquina 10 kg). Não deve gerar séries duplicadas, nem acima da carga de trabalho ou abaixo de zero. Teste em Task 2.
3. **Previsão com dados ruins:** um ponto só, tendência plana ou de queda, alvo já batido. Espera-se "sem previsão" ou "já bateu", nunca semanas negativas ou infinitas. Teste em Task 2.
4. **Refazer pesquisa com rotina própria:** os treinos antigos são arquivados (não apagados) e o histórico e os recordes ficam intactos. Teste em Task 6.
5. **Backup v1 importado depois da fase 2:** ajustes sem `onboarded`, `profile`, `sound`, `targets`. Deve importar e o app não deve reabrir a pesquisa para quem já tem treinos. Teste em Task 1.

### Task 2: Domínio dos recursos de treino (aquecimento, platô, previsão)

**Files:**

**Interfaces:**
- Produces:
  - `isWork(s: SetLog): boolean` = `s.done && !s.warmup`. `findPRs`, `sessionStats`, `exerciseSeries`, `muscleVolume` and `dayIntensity` only count work sets.
  - `warmupSets(workKg: number, eq: Equipment): SetLog[]` (all with `warmup: true, done: false`).
  - `plateau(exerciseId: string, sessions: Session[], today: Date): boolean`
  - `forecastWeeks(series: { day: string; maxKg: number }[], targetKg: number, today: Date): { weeks: number } | { reached: true } | null`

**Rules (the spec fixes these):**
- **Warm-up.** For barbell: bar 20 ×10, 50% ×8, 75% ×3. Each rounds down to a multiple of 2.5 (1.25 kg per side). Drop any that is ≤ the previous one or ≥ the work load. With `workKg ≤ 20`, return `[]`. Dumbbell and machine use 50% ×8 and 75% ×3, rounded to 2 (dumbbell) or 2.5 (machine/cable), same drop rule. Bodyweight returns `[]`.
- **Plateau.** Take the sessions containing the exercise within the last 21 days (`localDay`). If there are ≥ 3, and the best e1RM in that window is ≤ the best e1RM before the window, return `true`. Without history before the window, return `false`.
- **Forecast.**
  - Use the points from the last 56 days. With fewer than 3, return `null`.
  - If the last `maxKg` ≥ target, return `{ reached: true }`.
  - Otherwise run a least-squares linear regression of kg against days. A slope ≤ 0 returns `null`.
  - Then `weeks = ceil((target − last) / (slope × 7))`; above 104 returns `null`.

### Task 3: Gerador de plano a partir da pesquisa

**Files:**
- Create: `src/domain/plan.ts`
- Test: `tests/domain/plan.test.ts`

**Interfaces:**
- Consumes: `Profile` (Task 1), `EXERCISES` / `Exercise`.
- Produces:
  - `PLACE_EQUIPMENT: Record<Place, Equipment[]>`:
    - `completa`: all;
    - `basica`: `barbell`, `dumbbell`, `machine`, `bodyweight`;
    - `casa`: `dumbbell`, `bodyweight`.
  - `generatePlan(p: Profile, lib: Exercise[]): Template[]`: active templates with `order` 0..n−1; ids `plan-<letter>`; names `"A — Peito, ombro e tríceps"` style.
  - `planSummary(p: Profile): { split: string; why: string; reps: [number, number]; restSec: number }`: copy for the "Sua estratégia" screen.
  - `bmiCopy(kg: number, cm: number, age: number): { value: number; band: BmiBand; text: string }`: neutral, non-judgemental copy for the diagnosis.

**Rules (the spec fixes these):**
- **Split by number of days:**
  - 2 → Full body A/B;
  - 3 → ABC (beginner: Full body A/B/C);
  - 4 → Superior/Inferior A/B;
  - 5 → ABCDE (peito, costas, pernas, ombros, braços);
  - 6 → PPL ×2.
- **Reps and rest by goal:** massa 8–12 / 90 s; força 3–6 / 180 s; emagrecer and condicionamento 12–15 / 60 s.
- **Exercises by time:** 30 → 4, 45 → 5, 60 → 6, 90 → 7. Sets: beginner 3; others 4 on the first two (compounds) and 3 on the rest. Age ≥ 50 takes one set off compounds (minimum 3).
- **Beginners and age ≥ 50:** prefer `machine`, then `dumbbell`. Never `levantamento-terra`, `agachamento-livre`, `good-morning` or `nordic-curl` as the first exercise of the day.
- **Exercise choice:** a slot is a muscle, and the pick comes from an ordered preference list per muscle, filtered by `PLACE_EQUIPMENT[place]`, with no repeats within a template. If no candidate exists, take the next muscle in the same template.
